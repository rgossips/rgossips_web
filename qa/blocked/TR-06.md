# TR-06 — End-to-End & System Testing  [BLOCKED]

**Objective.** Validate complete business journeys in a production-like
environment, as a real user experiences them.

**Exit criterion.** All twelve journeys pass on Chrome; the four highest-traffic
journeys also pass on Chrome Android, Safari iOS and Firefox. Each journey passes
its failure-injection variant with correct rollback and user messaging.

## Blocker

Every journey mutates. "Brand creates campaign, creator applies, brand approves
with price, creator accepts, brand funds escrow…" writes campaigns, applications,
escrow rows, ledger entries and notifications. There is one Supabase project and
it is live, holding 1,693 real influencer profiles. Running this against it would
put synthetic campaigns in front of real creators and synthetic applications in
front of real brands.

Playwright is also not installed.

## Unblocks when

A staging project exists (see `qa/registers/environment.md`). Then:

1. `npm i -D @playwright/test && npx playwright install chromium`
2. Point `.env.local` at staging.
3. Seed via the already-deployed `seed-test-users` function.

## Spec to write

The lifecycle under test, from `list-campaigns` and CLAUDE.md:

```
pending → offer_sent → offer_accepted → approved (escrow held)
  → submitted → revision_needed → accepted → live_submitted → payment → completed
with rejected and withdrawn branching off
```

**Reconcile before writing A-05.** That is twelve statuses; the strategy's A-05
says "an application in each of the eleven statuses other than accepted-offer".
The counts only agree if one branch state is excluded. Settle which, or the
assertion is written against a number nobody verified.

Twelve journeys, each also run with an injected mid-flow failure:

1. **Creator onboarding** — role selection, mandatory Instagram Business Login,
   WhatsApp OTP with the 60s resend contract, categories, preferences, profile
   finalisation including avatar re-hosting and the 50 RC welcome grant.
   Note the deferred auth-user creation (Option A): no `auth.users` row exists
   until `create-profile` succeeds, and a forced profile failure must roll the
   auth user back. Assert zero orphans.
2. **Brand onboarding** — phone OTP, GSTIN capture and third-party validation,
   legal/trade name population. Brands now land `verification_status='pending'`
   and cannot publish until an admin verifies.
3. **Full priced deal** end to end, both parties rating.
4. **Withdrawal** from `pending` and from `offer_sent`; assert the campaign
   returns to the correct tab. This must now include the **Approved** tab added
   2026-08-24: a campaign at `applicationStatus === "approved"` appears under
   Approved and **not** under Applied.
5. **Barter campaign** variant.
6. **Subscription purchase and upgrade** across all three tiers, including RC
   redemption at checkout, proration and failed renewal. Razorpay's first-cycle
   discount uses a throwaway plan plus a deferred upgrade — assert cycle 2 bills
   at full price.
7. **Referral** — link issued, referee signs up, first purchase qualifies,
   credits land both sides, leaderboard and rank update.
8. **RC redemption** against a subscription invoice, at the cap boundary.
9. **Media kit** — generation, template switching within plan limits,
   publication, public rendering with correct preview cards.
10. **Service marketplace** order and payment.
11. **Dispute and refund** — escrow refunded, trust impact recorded.
12. **Invitation claim** by a matching handle; also the role-mismatch interrupt.

Failure injection per journey: kill the gateway mid-checkout, drop the webhook,
revoke the Instagram token mid-campaign, and 500 the edge function.
